**Key gotchas learned (reusable):**
- `useReducedMotion()` from motion reads the media query on the first client
  render → hydration mismatch. Use a wrapper that returns `false` on server +
  first client render, then applies the real value in an effect.
- Arabic/Persian glyphs lose cursive joins if split per character — split
  per **word**.
- Absolutely-positioned pin layers collapse to 0 height under reduced motion;
  provide a static grid fallback.
- CSS-Module specificity: `.experience button` (0,1,1) beats `.stickyNav button`
  (0,1,0) — new module selectors need ancestor qualification.

**Deliberately NOT ported:** `cursor:none`, animated marquee (original runs are
static), Tilda type-706 cart modal, tilda-slds product popups.

**Key gotcha (reusable) — CSS Modules hash EVERY class in a
selector, not just the first:**
- Compound: `.fadeUp.inView{...}` → `.hash__fadeUp.hash__inView`.
  Applying `className={`${styles.fadeUp} ${inView?'inView':''}`}`
  NEVER matches, because the literal `inView` is not hashed.
  **Entrance animations silently do nothing** (element stays at
  opacity 0). Same for `.imageScale.inView`,
  `.statementImage.inView img`.
- Descendant: `.scramble.isScrambling{...}` → both hashed, so
  `className="scramble isScrambling"` never matches either.
- **Fix: use attribute selectors.** `[data-in-view='true']`,
  `[data-blur-active='true']` + `data-in-view={inView || undefined}`
  in JSX. For ancestor-driven triggers use
  `.experience [data-in-view='true'] .headingArrow svg path`.
- **And always reference hashed classes via `styles.X`** — a bare
  `className="blurWord"` is a no-op even when `.blurWord` exists in
  the module.

**Audit script that caught this:** `scripts/v21-anim-audit.mjs`
counts `[class*="fadeUp"]` / `[class*="blurWord"]` /
`[class*="imageScale"]` / `[class*="headingArrow"]` and compares
total vs. how many actually reached their visible state
(`opacity>0.9`, `data-in-view`, `strokeDashoffset<5`). Final run:
blurWord 16/16, fadeUp 16/16, imageScale 9/9, arrows 4/4, 0 errors.
**Always run an audit like this after wiring scroll animations** —
"the page renders" is not proof the animations fire.

**Hydration mismatch on `prefers-reduced-motion`** (caught by
`scripts/v21-rm-check.mjs`): `useReducedMotion()` from framer-motion
returns the actual media-query value on the first client render but
the server has no `matchMedia`. Hero video `previewPaused` and the
play/pause icon `aria-label` differ → React hydration error on every
page load for users with reduced motion. **Fix: mount-gate it.**
```ts
function useReducedMotionSafe(): boolean | null {
  const reduced = useReducedMotion();
  const [mounted, setMounted] = useState(false);
  useEffect(() => setMounted(true), []);
  return mounted ? reduced : false;
}
```
Same pattern documented for `/v19` — apply it everywhere
`useReducedMotion()` is consumed, not just the MotionConfig root.

**Reusable reduced-motion test:** Playwright supports
`newContext({ reducedMotion: 'reduce' })`. Audit both modes side by
side, then assert `PAGEERR`/`CONSOLE` counts are 0 in both. Don't
assume reduced-motion is handled because animations "look paused" —
verify with a hydration-error grep.

**Why some Reveals were removed:** horizontal sliders (team, press,
merch) must always render their items — wrapping each card in a
`<Reveal>` that starts opacity 0 makes the whole slider look empty in
static screenshots and for users who never scroll. Items inside
horizontal scrollers should NOT be Reveal-wrapped.

**Key gotchas (reusable):**
- **Stacking context traps fixed overlays.** `.if-container { z-index: 2 }`
  creates a stacking context, so a `position: fixed` child is trapped
  *below* the fixed `.if-rail` (z-index 70) **no matter how high its own
  z-index is**. Symptom: lightbox "next" button unclickable
  (`<nav class="if-rail"> intercepts pointer events`). **Fix: render fixed
  overlays (`Gallery`, `QuizModal`, `VideoModal`) as siblings OUTSIDE any
  `z-index`ed ancestor** — wrap only the inner grid in `.if-container`.
  Diagnose with `document.elementFromPoint` probing.
- **One tween per `transform`.** `[data-if-reveal]` elements are already
  staggered by the generic GSAP reveal in `Landing.tsx`. Adding a second
  tween that also writes `transform` to the same node makes them fight.
- **`react-hooks/set-state-in-effect`**: a state-reset effect in the quiz
  tripped it. Replaced with a **remount key** (`key={quizKey}`, bumped in
  `openQuiz`) — cleaner and lint-clean.
- **Next 16 dev server 403s on `Origin` mismatch.** Testing against
  `http://127.0.0.1:PORT` returns **403 on every `/_next/static/chunks/*.js`**
  so nothing hydrates. Use `http://localhost:PORT`. (`--noproxy '*'` needed
  for curl because the env forces `HTTP_PROXY`.)
- **Parallax vs. hover-zoom collide on the same `<img>`.** Put the GSAP
  parallax on a dedicated wrapper (`.if-program-parallax`) so the `<img>`
  keeps its own CSS hover-zoom `transform`.
- **Drag interactions: write the CSS custom property directly**
  (`--if-ba`) instead of React state — no re-render per pointermove.
  `clip-path: inset()` does the reveal; Pointer Events +
  `setPointerCapture` unify mouse/touch/pen.
- **IDE save races silently reverted edits 3×** (`ScrollCue` import,
  `quizKey`, `onStart`). Always grep-verify critical wiring after editing
  in this workspace.

**Dev-only console noise (NOT defects — verified):**
- A React **hydration mismatch on the News arrows**
  (`disabled={true}` vs `disabled={null}`) appears only in browsers with
  **extensions**. `idx` and `max` are both `0` on server *and* first client
  render, so the markup is identical by construction. A clean Playwright
  profile reports **0 hydration warnings / 0 console messages**.
- `prefersReducedMotion is not defined` in the dev log was a **stale error
  from an intermediate edit**; the helper is defined at `Landing.tsx:37`.
- The News "next" arrow renders `disabled` until the `ResizeObserver`'s
  first measurement makes `max` non-zero — a normal post-hydration state
  update, not a mismatch.
