## Marketing — WhatsApp outreach kit for doctors/clinics (Persian)

Wrote `marketing/whatsapp-outreach-fa.md`: a cold-outreach kit for DMing
doctors one-by-one on WhatsApp to sell doctor/clinic websites.

Key decisions baked into the kit:
- **Booking is the hook**, not "a website". Lead with the appointment pain
  (phone busy / missed after-hours calls / cancellations).
- **No link in the first message** — link only after the doctor replies.
  Same for PDFs and voice notes (text first, then voice).
- Message 1 stays under ~400 chars, always personalised with name + specialty.
- Max 2 follow-ups (day 3–4, day 7–8), then stop. 10–15 msgs/day on a fresh
  number, up to 20–25 after warm-up. Sat–Wed, 10–13 & 17–20.
- Proof asset = 20–30 s screen recording of the `/v1` booking funnel
  (OTP → patient → doctor → slot → fee), sent only after interest.
- Highest-converting move documented: build a **mini-demo under the doctor's
  own name/specialty** for free, since every `/vN` route is already a
  rename-away from being "his" site.

Route inventory used as examples: `/v1` کلینیک ۴۰۴ (full booking flow, 74
`نوبت` mentions, real `/booking` + `/appointments` routes) and `/v8` کلینیک
قلب مهر as the two named samples; `/v2`, `/v6`, `/v9`, `/v10`, `/v13` listed
as the "want more?" menu. Doctor/clinic routes overall: v1–v14 (v12/v13/v14
have no booking copy yet — v13 is psychotherapy, could use one).

- **Angle changed from "a website" to three hooks:** (1) محرمانگی — patients

  (3) pregnancy/screening/fertility recall reminders to kill no-shows.

  in the WhatsApp text (she may read it in front of a patient or family), never
  compliment her appearance, no voice note before she replies, prefer sending
  from a female colleague's number if available.

  **C Instagram**, **D recall** (strongest for OB/GYN), E one-liner for A/B.
- Added an Instagram-objection reply ("پیج اینستاگرام دارم، همین کافیه").
- Contact priority order: beauty/skin with an active IG page → OB/GYN &
  fertility → other female-majority specialties (لیزر، پوست).

## Built: /outreach console (answering "can I send from my app?")

**The answer to that question, and the reason this exists:** there is no way to
bulk-send from a personal WhatsApp number via any official API (Meta's Cloud
API needs a WABA on a *dedicated* number + Meta verification + pre-approved
templates), and unofficial automation (Baileys / whatsapp-web.js) violates
WhatsApp ToS and gets a personal number banned within the first few hundred
cold messages. So the console does the only thing that works with the user's
own number: it owns the queue, the personalization and the tracking, and each
send is one click that opens WhatsApp with the text pre-filled via
`wa.me/<digits>?text=`.

Files: `app/outreach/{page.tsx,outreach-console.tsx,outreach.module.css}`,
`app/outreach/lib/{types.ts,templates.ts,store.ts,settings.ts}`,
`app/api/outreach/status/route.ts`.

- **Gated behind `OUTREACH_ENABLED="true"`** (page + API both `notFound()`/404
  otherwise) because the page renders real phone numbers. Added to the local
  `.env` only.
- Contacts come from `data/outreach/contacts.json`, built by
  `scripts/build-outreach-contacts.mjs`; status lives in
  `data/outreach/state.json`. **`/data/outreach/` is gitignored** — real phone
  numbers must never be committed. No Prisma model on purpose (no migration,
  no chance of shipping contact data with the app).
- **Pitfall:** the client console must NOT import `store.ts` (it pulls in
  `node:fs` into the browser bundle) — shared types/labels live in
  `lib/types.ts`.
- **Pitfall:** settings are hydrated with `useSyncExternalStore`
  (`lib/settings.ts`), not `useState`+`useEffect`. The repo's eslint has
  `react-hooks/set-state-in-effect` as an **error**, so the effect-based
  localStorage hydration pattern fails lint.
- Daily quota (default 25) is enforced by slicing the queue, and
  `sentAt`/`followUpAt` (+3 days) are stamped server-side in `patchContact`.

## The contact list (C:\Users\aria\Desktop\contact-doctors)

1,638 numbers, OCR'd from ~100 screenshots. Real composition:
**1,624 Iranian mobiles (+98 9xx)**, only 14 international (US/CA, ES, DE, OM,
AE, IQ, AF). Names were recoverable for **1,201** by parsing `ocr_raw.json`
(name = nearest non-number line above each number); **283 display names start
with "Dr"** → these are the actual doctors and the top of the queue. Only ~8
had a specialty in the name (OB/GYN etc.), so specialty targeting has to come
from reverse lookup, not from the list.

- Name cleaning matters: WhatsApp default statuses ("Hey there! I am using
  WhatsApp", "In a meeting") and OCR noise ("V.45", "YY.45") get filtered out
  by the `JUNK`/`cleanName` rules in the build script.
- Reverse-lookup sources confirmed by search: **paziresh24.com**, doctoreto.com,
  arenap.ir, plus WhatsApp Business profile and Google-with-quotes on the
  number.
- Volume reality: 1,638 at a safe 20–25/day ≈ 2.5–3 months. Start with the 283
  Dr-flagged contacts.

## Copy + priority revision (operator feedback)

Three standing rules the operator set, now enforced in code:

1. **Colloquial (شکسته), not formal.** Rewrote every template — «میاد»,
   «می‌بینه», «راه می‌ندازم», «نیستن», «می‌ندازن». The probe now asserts BOTH
   that colloquial markers are present AND that formal markers
   (`می‌آید|نیستند|می‌باشد|…`) are absent, so the copy can't silently drift back.
2. **No sender name and no doctor name in the message text.** Removed the
   `{name}`/`{me}` placeholders, the `needsName` field and the name-fallback
   logic; dropped the «نام شما» field from console settings. The doctor's name
   is still extracted and shown **in the console UI only** (useful for
   identification/reverse lookup) — `displayName()` stays, but is never
   interpolated into a message.
3. **Priority tiers.** `scripts/build-outreach-contacts.mjs` now stamps
   `prefix` + `tier` on every contact: **tier 1 = +98913 (195 numbers)**, tier 2
   = rest of Iran (1,429), tier 3 = outside Iran (14). The console defaults to
   tier 1, sorts by `tier*10 + doctorRank`, and shows tier buttons.
   Prefix distribution of the list: 912→618, 911→226, 913→195, 914→114,
   917→98, 915→91, then a long tail.
