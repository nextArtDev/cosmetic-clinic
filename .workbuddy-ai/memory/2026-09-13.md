## Root-caused bug: RTL killed every marquee
`.maya-scrollrow` / `.maya-scrollrow-track` needed
**`direction: ltr`**. Under `direction: rtl`, a `width: max-content`
track overflows to the *LEFT* of its `overflow: hidden` parent, so the
`xPercent: 0 → -50` loop walked it entirely off-screen — all 24
video-overlay text spans were outside the viewport (hit-test returned
`.maya-scrollrow` instead of the span). Fixing the CSS restored every
`MayaMarquee` on the route. Persian runs keep their own bidi ordering.

## Deliberate deviations (documented in the route README)
- `mixAndMatchBundle` also applies `y: -cardHeight/2`, but that is
  compensation for a wrapper the engine shortens by the same amount. We
  don't clip the grid, so only the differential `yPercent: -10`
  (duration 1.2 vs 2) is kept — otherwise a ~250px hole appears at the
  bottom of the section.
- Layouts that the original renders very differently (FeaturedTabs'
  centred pill strip, BestSellers' fanned title stack) keep the Iranized
  layouts; the *motion vocabulary* (pin, scrub, stagger, char reveal,
  roll) was ported onto them rather than rebuilding from scratch.

### Shape library (follow-up)
`MASK_SHAPES` now holds 15 generated paths on one 356×356 canvas
(`star` = verbatim v2 flower, `sparkle`, `burst`, `petals`, `blob`,
`circle`, `squircle`, `diamond`, `hexagon`, `leaf`, `arch`, `cross`,
`heart`, `mosaic`, `blinds`), built by small helpers (polygon, spiky,
rosette, smoothClosed/blob, roundedRect, tiled). Exported
`MASK_SHAPE_LIST` for pickers.
Key constraint discovered: a single-percentage `mask-size` derives height
from the SVG's intrinsic ratio, so **every shape must share one viewBox**
or the outline SVG and mask drift apart.
Coverage: pointy/tiled shapes can never cover a tall viewport's corners
(v2's 340% leaves corners on mobile), so a second **unmasked AFTER twin**
fades in from `solidAt` (0.86) → guaranteed full-frame finish for any
shape. Outline disabled when `maskSrc` overrides the built-ins.
Verify generated geometry with a throwaway `npx tsx` script that imports
`MASK_SHAPES` and dumps the `d` strings — catches bad path math fast.

## Fixed mobile scroll mismatch in the two home before/after sliders
Measured on a real Chromium iPhone-13 viewport (390x664) against the dev
server at :3000 with a Playwright probe (system Chrome via
`playwright-core` + `channel: 'chrome'` — no browser download needed).

Root causes found (all confirmed by measurement):
1. `BeeforeAfterReveal.tsx` halved `scrollVh` (220 -> 110vh) for phones,
   but the sticky stage already eats 100vh of that, so the *runway* went
   120vh -> 10vh. Measured: 66px total runway, wipe finished in 45px.
2. Both components used `end: 'bottom bottom'`, but ScrollTrigger resolves
   the viewport as 100vh = **large** viewport (internal `_div100vh` probe,
   not `window.innerHeight`) while the stage is `100svh`/`100dvh`. On real
   phones that gap (= URL-bar height) is a dead zone: progress hits 1 while
   the section is still pinned.
3. `BeforAfterScrollSlider` ran a ~2.3s intro auto-demo that owned the seam
   (`if (introPlaying) return`) — on a 332px mobile runway the user had
   already scrolled past. Its return tween also targeted a `scrollProgress`
   captured when the tween *started*, parking the seam at a stale value.
4. The 0.06 lerp added ~0.8s catch-up; scrub was inert in the reveal
   slider (`scrub` only smooths an *attached* animation, not a bare
   `onUpdate`).

Fixes: derive `end` from `section.offsetHeight - pinned.offsetHeight`
(`+=N`, `invalidateOnRefresh`), scale only the runway on phones
(`100 + (scrollVh-100)*0.5`), stage `h-dvh` -> `h-svh`, skip the intro on
compact viewports, hand back to live `scrollProgress` on intro complete,
compact lerp 0.16. Result: seam catch-up after a flick 1300ms -> ~450ms;
reveal runway 66px -> 398px. Desktop geometry unchanged (verified 1440x900).

Note: `MaskRevealCompare.tsx` (120svh) still mixes an svh section with
ScrollTrigger's lvh viewport — same class of dead-zone bug, not yet fixed.
