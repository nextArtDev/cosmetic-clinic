## /v24 — numa.uprock.pro port, brought to green

Finished the /v24 port of `numa.uprock.pro` (builder-generated Taptop/Mosaic page,
Russian, insulin pump) as a Persian dental-clinic route.

### The decisive bug, found and fixed
Scroll-scrubbed elements were snapping to their final keyframe. Root cause: the
reference's `getScrollTrigger()` returns a **vars object** handed straight to
`gsap.timeline({scrollTrigger: vars})`. I had been pre-creating a `ScrollTrigger`
instance and passing that — GSAP does **not** adopt an existing instance that way,
so every scrubbed timeline was unlinked and played freely to completion at build
time. The numbers strip sat at `x = -265.83vw` at 8% of its travel.
Fix: pass the vars object. Evidence: `desktop-01` 52 KB → 592 KB, `desktop-09`
8.4 KB → 829 KB.

### Fidelity gaps closed against the reference's own `tt_animation.js`
- `APPEAR_ON_SCREEN` `toggleActions` was `'play none none reverse'`; the
  reference's default is `'play none restart reset'` (`'play none none none'`
  only when `iterations === 1`). Corrected.
- Only the **first effect of each property name** gets `immediateRender: true`;
  the rest are explicitly false, otherwise two `fromTo`s at position 0 both
  render immediately and the later one's "from" state stomps the earlier. Applied
  to both the APPEAR and HOVER/CLICK branches. The reference keys this off effect
  ids, which the extraction dropped, so source order stands in for them.
- HOVER branch no longer coerces `duration || 0.001` (that changed effects with no
  declared duration from GSAP's default to 0.001). Now matches the reference's own
  guard: nudge off zero only when `immediateRender && duration === 0`.

### Two probe false negatives worth remembering
The probe's original assertions were themselves wrong, and chasing them cost real
time:
1. **HOVER-triggered elements rest at `opacity: 0` by design** — they are
   hover-revealed overlays. Counting them as "unpainted" is a false negative.
2. **"Hidden at this instant" is not a failure.** The reference's own data fades
   elements out mid-travel (`ir5h3h6ou` fades in 35–43%, holds to 69%, fades out
   by 77%). Asserting "everything is painted after a full scroll pass" is simply
   the wrong assertion. The real failure signature is an element hidden across its
   *entire* travel. The probe now sweeps each trigger's span (widened by a
   viewport each side, so triggers shorter than the viewport are covered) and
   asserts every one of the 80 scrubbed elements lights up somewhere.

Also: the React "non-boolean attribute" console error in the probe output comes
from the **host home page** (`/`), not `/v24` — verified by attributing console
messages per page. Pre-existing, not mine.
